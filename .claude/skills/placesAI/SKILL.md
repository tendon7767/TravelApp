# placesAI

替一趟旅程裡指定的幾個地點查資料，把結果寫成行程說明裡的「AI資訊」區塊與備註。

App 裡的 ✨ 按鈕走 Gemini，**免費層拿不到搜尋 grounding**，只能靠模型記憶。
這條路用的是這裡的 WebSearch，所以內容是真的查過的 —— 這是它存在的唯一理由。
不要在這裡憑印象寫，那樣就跟按鈕沒有差別，而且更慢。

## 流程

**每一步都要做完再進下一步，不要一路跑到底。**

### 1. 列出候選

```bash
npx tsx scripts/places.ts list <旅程代號>
```

（先 `export PATH="$HOME/.local/node/bin:$PATH"`。）

輸出是 JSON，欄位有 `id` / `date` / `time` / `title` / `category` / `hasMap` / `hasAi` /
`mapUrl` / `guide` / `notes`。

沒有設定檔的話它會印出格式並結束——那時候跟使用者要那趟的邀請連結，
寫進 `~/.travelapp/trips.json`。**那個檔案在 repo 外面，不要搬進來**：
邀請連結就是通行證，而 `.claude/` 是進 git 的。

### 2. 算繪成編號清單給人看

**預設只列 `hasMap === true` 且 `hasAi === false` 的**。跑過的不再跑，
所以隔天再叫一次只會看到新加的那幾筆。

照日期時間排，一天一組：

```
這趟有 12 個地點還沒有 AI資訊：

  8/14
   1. 12:00  淺草今半
   2. 15:00  淺草寺

  8/15
   3. 10:00  金閣寺
   ...

要跑哪幾個？（編號、範圍，或 all）
```

`hasMap === false` 的**不要列進主清單**，在最後補一行「另有 3 筆沒有地圖連結，跳過」。
沒有座標會查到同名的別家店，這是 App 那邊也在守的規則。

使用者要重跑已經有 AI資訊 的，或指定某一天、某個關鍵字，就照他說的挑。

### 3. 等他選，然後才開始查

**不要自作主張跑全部。** 他明講的量長什麼樣就跑什麼樣。
超過 15 筆的話先問一次「這樣是 N 筆，確定？」——查是要花時間的。

### 4. 查

每一個地點用 WebSearch。判斷準則、要寫什麼不寫什麼、語氣、
`cautions` 要寫成「要去確認的事」而不是斷言——**全部照
[src/data/placePrompt.md](../../../src/data/placePrompt.md) 那份**。
先讀它再開始寫，不要憑記憶重述那些規則。

那份檔案是 App 的 ✨ 按鈕在用的 system prompt。**共用它是刻意的**：
使用者調 prompt 的時候，兩條路要一起改變，否則產出會慢慢長歪。

差別只有一個：那份寫「如果你有搜尋工具可用」，在這裡你**一定**有，所以
`userreviews` 該填、營業時間類的資訊查得到就可以寫（照它的措辭要求）。

`mapUrl` 裡的座標拿來確認是哪一家分店。`guide` 與 `notes` 是使用者已經寫過的，
不要重複。

### 5. 寫回去前先報告

```
要寫 6 筆：
  · 淺草今半、金閣寺、⋯⋯（4 筆查到資料）
  · 岡山 400℃、⋯⋯（2 筆查不到，會留空）
繼續？
```

查不到就照 prompt 的規則留空，**不要為了不空手而編**。全部都查不到就直說，不要寫。

### 6. 寫

payload 是 `[{ "id": "...", "place": { ... } }]`，`place` 的形狀就是
`src/lib/placeInfo.ts` 的 `PlaceInfo`（八個欄位都要有，沒內容給空字串或空陣列）。

```bash
npx tsx scripts/places.ts write <旅程代號> < /tmp/.../payload.json
```

它會回報寫入與被拒的筆數。**被拒不是錯誤**——後端會擋掉 `updatedAt` 比現有列舊的記錄，
表示那筆在這中間被別人改過，重跑一次就好。

寫完提醒使用者在 App 裡同步一次才看得到。

## 不要做的事

- **不要碰 `guide` 和 `notes` 以外的欄位。** 這是直接寫進同步層、繞過 App 自己的寫入邏輯，
  動到的欄位愈少愈好。腳本已經幫忙把其餘欄位原樣帶回，不要想辦法繞過它。
- **不要自己組「AI資訊」那段文字。** 排版由 `formatPlaceInfo` 決定，腳本會呼叫它。
  自己拼一份出來，格式就會跟 App 那條路長歪，之後在 App 裡重新分析也切不乾淨。
- **不要把旅程密鑰寫進 repo 裡的任何檔案**，包括 `.claude/`。
- 第一次替某趟旅程跑的時候**只做一筆**，讓使用者去 App 看過再放開。
